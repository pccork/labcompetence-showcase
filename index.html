What this app is for

A digital alternative to fragmented training administration

The portal was created to make laboratory competence management easier to run, easier to review, and easier to audit. Instead of relying on paper forms, manual follow-up, and disconnected spreadsheets, it brings assignments, records, due dates, template versions, and training evidence into one governed workflow.

It supports both ordinary laboratory sections and Point of Care Testing workflows, where large numbers of medical and nursing staff may need training through QR-based self-registration.

Why it matters

  • Improves visibility of training status and renewal risk
  • Creates a clearer audit trail for accreditation evidence
  • Reduces admin effort for coordinators and section trainers
  • Supports multi-hospital growth without redesigning the model

Key workflows

Two clear pathways: core laboratory training and POCT onboarding

Ordinary laboratory training workflow

  1. Coordinators create users, sections, and reusable training templates.
  2. Staff are assigned to section-specific training with renewal intervals and due dates.
  3. Training takes place with support from a trainer or section lead.
  4. Evidence, assessment notes, dates, and sign-off details are recorded digitally.
  5. Completed records are retained against the correct template version for review and audit.

POCT self-registration and response workflow

  1. A coordinator creates a QR registration link for a POCT section or device.
  2. A medical or nursing user scans the code and submits a training request.
  3. The portal groups requests by hospital, device, location, and status.
  4. A coordinator or trainer replies with training time, location, and instructions.
  5. Face-to-face training is completed and the digital record is stored for future renewal tracking.

Technical architecture

How the Lab Competence Portal is structured

The prototype follows a practical three-layer web architecture: React provides the user-facing experience, Fastify handles the API and business workflow layer, and PostgreSQL stores the relational training data that connects users, templates, assignments, sections, hospitals, and records.

Presentation layer

React frontend

Rich component libraries and modern SPA patterns support dashboards, login, role-based views, POCT registration flows, and responsive stakeholder-facing screens.

↓

Application layer

Fastify backend API

Fastify gives the project a lightweight, flexible, and expandable service layer for routing, validation, RBAC, workflow logic, and future growth as the portal evolves.

↓

Data layer

PostgreSQL relational database

PostgreSQL is well suited to building the related data model behind staff, training templates, assignments, competency records, hospital scope, and audit-ready history.

Why React

React supports a richer UI ecosystem, making it easier to assemble dashboard panels, forms, reusable components, and future workflow enhancements.

Why Fastify

Fastify keeps the backend fast and modular, which helps when adding new routes, hospitals, staff rules, integrations, or workflow features over time.

Why PostgreSQL

A relational database is important here because competence management depends on clear links between people, roles, sections, templates, version history, and due dates.

Prototype status

Current state of the proof of concept

The current implementation is a working proof of concept with a React frontend, a Fastify backend, and a PostgreSQL database. It already supports role-based access, hospital-scoped data, template versioning, training assignments, training records, and POCT request handling.

The Render deployment blueprint is configured as a cost-conscious prototype: a static frontend, a starter backend service, and a basic managed Postgres database. This showcase site is separate and intentionally simpler so it can be deployed directly to GitHub Pages without a build step.
